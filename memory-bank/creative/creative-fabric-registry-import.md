# План: импорт реестра материалов (ткани) из Excel

**Источник:** `Реестр_материалов_МФ_Анна_v2.xlsx`, лист **«Ткани и кожа»** (+ лист **«Справочники»**).  
**Точка входа в админке:** `/admin/fabric-collection/index` → блок «Импорт из реестра».  
**Стек:** Yii2 console + admin UI, `phpoffice/phpspreadsheet`.

> **Статус:** планирование. Решения по цветам и конфликтам зафиксированы (§4, §5, §11). Формат фото в Excel — целевой (§5), в текущем файле ещё нет.

---

## 1. Цель

Из одного Excel-файла создавать/обновлять:

| Сущность | Таблица | Из строки Excel |
|----------|---------|-----------------|
| Фактура (коллекция ткани) | `catalog_fabric_collections` | **Коллекция** (кол. C) + общие поля коллекции |
| Цвет (группа) | `catalog_colors` | **Цвет (группа)** (кол. I) — только из глобального справочника |
| Цветодизайн в коллекции | `catalog_fabric_collection_colors` | **Цветодизайн** (кол. D) + тех. поля + фото/PBR/сертификат |
| Ценовые категории | `catalog_price_categories` | лист «Справочники» + кол. F/G |
| Фото образца | `media_files` → на связи коллекция+цвет | кол. O (приоритет), P как fallback |
| Сертификат | `media_files` → на связи | кол. Q |

SKU и модели **не создаём** на этом этапе (отдельный импорт листа «3D-модели» + связь «Применяется на модели», кол. N).

## 2. Что должно быть в ткани (поля и размещение)

### 2.1. Уровень коллекции (`catalog_fabric_collections`)

| № | Поле в системе | Колонка Excel | Лист | Примечание |
|---|----------------|---------------|------|------------|
| 1 | **Категория ткани** `material_kind` | Категория (B) | Ткани и кожа | Расширяемый enum: `Ткань` (по умолчанию), `Кожа`, `Экокожа`, `Спец. покрытие`. Пустое значение → `Ткань` |
| 2 | **Коллекция** `name` | Коллекция (C) | Ткани и кожа | Upsert по slug |
| 5a | **Категория для коллекции А+** `price_category_id` | Категория для коллекции А+ (F) | Ткани и кожа | FK → `catalog_price_categories`, парсинг номера из подписи |
| 5b | **Категория для коллекции Линия 1** `price_category_line1_id` | Категория для коллекции Линия 1 (G) | Ткани и кожа | FK → `catalog_price_categories` |
| 6 | **Фактура** `texture` | Фактура (H) | Ткани и кожа | Велюр, Букле, Шенилл… |
| 12 | **Доступные цвета коллекции** | Доступные цвета коллекции (R) | Ткани и кожа | Текст/список на коллекции или разворот в отдельные цветодизайны (см. §5.3) |
| — | **Уход** `care_instructions` | — | *нет в Excel* | Новое поле, заполняется вручную в админке |

### 2.2. Уровень связи коллекция + цветодизайн (`catalog_fabric_collection_colors`)

Одна строка Excel = одна связь `(коллекция, design_code)`.

| № | Поле в системе | Колонка Excel | Лист | Примечание |
|---|----------------|---------------|------|------------|
| 3 | **Цветодизайн (название)** `design_code` + `design_label` | Цветодизайн (D) | Ткани и кожа | `design_code` — нормализованный ключ (`4.0`→`4`); `design_label` — как в Excel. **Новое поле**, если в схеме нет |
| 4 | **Состав** `composition` | Состав (E) | Ткани и кожа | |
| 7 | **Цвет** → `color_id` | Цвет (I) / «Цвет (группа)» | Ткани и кожа | Ссылка на `catalog_colors`. **Может быть пустым** — импорт связи без цвета (§4.4) |
| 8 | **Износостойкость** `martindale` | Martindale (J) | Ткани и кожа | Циклы Мартиндейла, int |
| 9 | **Свойства** `properties` | Свойства (K) | Ткани и кожа | text |
| 10 | **Ширина рулона, см** `roll_width_cm` | Ширина рулона (L) | Ткани и кожа | smallint |
| 11 | **Плотность, г/м²** `density_gsm` | Плотность (M) | Ткани и кожа | smallint |
| — | **Применяется на модели** | (N) | Ткани и кожа | Фаза 2 — очередь связей с моделями |
| — | **Фото фактуры** `swatch_media_id` | Фото фактуры (O) | Ткани и кожа | MediaFile, **отдельно для каждого цветодизайна в коллекции** |
| — | **Текстура PBR** `pbr_media_id` | Текстура PBR (P) | Ткани и кожа | MediaFile (document/zip); если O пусто и P — картинка, P как swatch |
| 13 | **Сертификат** `cert_media_id` | Ссылка на СЕРТИФИКАТ (Q) | Ткани и кожа | Загрузка файла по URL → MediaFile |
| — | **Комментарий** `import_comment` | Комментарий (S) | Ткани и кожа | |
| — | **Исходная ссылка на фото** `source_photo_url` | (O) | | Для повторного импорта / очереди |

### 2.3. Глобальный справочник цветов (`catalog_colors`)

| Поле | Источник | Примечание |
|------|----------|------------|
| `label` | Колонка «Цвет» (сейчас I «Цвет (группа)») | **Только простые естественные названия:** терракота, бежевый, белый, серый… |
| `slug` | auto из label | |
| `hex_color` | вручную в админке | опционально |
| `swatch_media_id` | **не для импорта** | Фото — на связи (§2.2) |

**Правила создания цветов при импорте (§4.4):**
- Создаём запись в справочнике **только** если название — простое слово/словосочетание из списка естественных цветов.
- **Не создаём:** `{Коллекция} {Код}`, коды (`422`, `4.0`), торговые имена (`Savana Terracotta`).
- Если цвета нет в справочнике, но название валидное — создать `catalog_colors` автоматически.
- Если колонка «Цвет» пустая — связь импортируется **без** `color_id` (`NULL`).

### 2.4. Ключ уникальности и проверка дубликатов

```
(fabric_collection_slug, design_code_normalized)
```

`design_code` = нормализация колонки D (код цветодизайна).

**Проверка при добавлении цвета (ручная и импорт):** уникальна пара **коллекция + код цветодизайна**. Цвет (группа) в ключ **не входит**.

**При конфликте** (в коллекции уже есть такой `design_code`, а в строке другие данные или повтор при импорте без `--update`):

1. Зафиксировать в отчёте: коллекция, код, что уже есть в БД, что пришло из файла.
2. **Приостановить импорт** с вопросом пользователю.
3. Варианты: **продолжить** (пропустить строку / перезаписать — по контексту) или **отменить** весь импорт.

В dry-run конфликты показываются в предпросмотре без паузы.

## 3. Ценовые категории и справочник Excel

### Лист «Справочники» в Excel

Содержит таблицу категорий ткани с **диапазоном стоимости** (номер категории + подпись вида `3 кат (от 801 до 900 руб)`).

### В системе

| Что | Где сейчас | Что нужно |
|-----|------------|-----------|
| Справочник категорий | `catalog_price_categories` (Настройки) | Расширить: `price_min`, `price_max` (или `range_label`) для диапазона |
| Импорт диапазонов | — | При импорте Excel — upsert категорий из листа «Справочники» |
| Редактирование в тканях | только dropdown в форме коллекции | **Новый блок** на странице «Ткани»: таблица категорий с редактируемым диапазоном (inline или отдельная вкладка) |
| На коллекции | `price_category_id` | Кол. F → А+; кол. G → Линия 1 (`price_category_line1_id`) |

Парсер подписи: `PriceCategoryLabelParser` — `"3 кат (от 801 до 900 руб)"` → `number=3`, `min=801`, `max=900`.

## 4. Цвета: ручное добавление и импорт

### 4.1. Принцип (уточнено заказчиком)

При добавлении цвета в коллекцию указываем **три вещи**:

1. **Цвет** — из глобального справочника (`catalog_colors`, кол. I)
2. **Код цветодизайна** — `design_code` (кол. D)
3. **Фото** — swatch **на этой связи**, не в глобальном справочнике

### 4.2. UI (целевой)

Заменить/дополнить текущий виджет «Цвета из справочника»:

- Кнопка **«Добавить цвет»** → **модальное окно**:
  - select: цвет из справочника (или ссылка «создать в настройках»)
  - input: код цветодизайна / название
  - media picker: фото образца
  - опционально: PBR, сертификат (фаза 3)
- Таблица цветов коллекции: цвет (группа) | код | превью фото | состав | Martindale | … | редактировать | удалить

### 4.3. Импорт из Excel

```
1. Upsert catalog_colors по label = колонка «Цвет» (если не пусто и название валидное)
2. Upsert связь catalog_fabric_collection_colors:
     design_code / design_label = колонка D
     color_id = из шага 1 или NULL
     тех. поля E, J–M, S
3. Проверка дубликата (коллекция + design_code) → конфликт → пауза (§2.4)
4. Медиа по правилам §5
```

### 4.4. Решения по цветам (зафиксировано)

| Ситуация | Поведение |
|----------|-----------|
| Колонка «Цвет» пустая | Импорт **без цвета** (`color_id = NULL`), строка не пропускается |
| «Бежевый» нет в справочнике | Создать `catalog_colors` с простым названием |
| Название не простое (код, коллекция+код) | Не создавать цвет; связь без `color_id` + предупреждение в отчёте |
| Дубликат коллекция + код | Ошибка → пауза → продолжить или отменить (§2.4) |

**Примеры валидных названий:** терракота, бежевый, белый, серый, зелёный, синий, чёрный.  
**Примеры невалидных (не в справочник):** `422`, `Leonardo 4`, `Savana Terracotta`.

## 5. Фото: текущий файл и целевой формат Excel

### 5.1. Текущий файл Анны v2

- Одна ссылка на фото в колонке O (на строку / цветодизайн).
- Часто: папка облака, заглушка, текст «снять фотографом».
- **Правило:** нет прямой ссылки на один файл или ссылка ведёт на **множество** тканей (папка) → **фото для этой позиции пропускаем**, материал импортируем без swatch. В отчёте: `photo_skipped`.

### 5.2. Целевой формат (будет в итоговом реестре)

Три колонки с **одинаковым порядком** значений через запятую — по одному элементу на каждый дополнительный цветодизайн из палитры коллекции:

| Колонка | Содержимое | Пример |
|---------|------------|--------|
| **Ссылки на фото** | URL через `,` | `https://…/a.jpg, https://…/b.jpg` |
| **Доступные цвета коллекции** (коды) | коды цветодизайна через `,` | `4, 5, 6` |
| **Цвет** | простые названия через `,` | `бежевый, серый, белый` |

Парсер разбивает три списка и **сопоставляет по индексу** (1-й URL → 1-й код → 1-й цвет).

```
codes[0]=4      colors[0]=бежевый    urls[0]=https://…/a.jpg  → связь Leonardo/4, бежевый, фото a
codes[1]=5      colors[1]=серый      urls[1]=                   → связь Leonardo/5, серый, без фото
```

**Правила для каждой тройки:**
- Нет URL или URL на папку / несколько файлов → связь создаётся, **фото пропускается**.
- Нет кода в списке кодов → пропуск позиции или предупреждение (TBD при появлении колонок в файле).
- Основная строка (кол. D, I, O) — как сейчас; колонки с запятыми — **дополнительные** цветодизайны той же коллекции.

### 5.3. Разворот колонки R (промежуточный вариант, пока нет трёх колонок)

Пока в файле только кол. R без параллельных списков URL и цветов:

| Значение R | Действие |
|------------|----------|
| `вся палитра` | сохранить в `available_colors_note`, без автосоздания |
| `4, 5, 6` | доп. связи с `design_code` из списка; цвет и фото — из основной строки или пусто |
| `Terracotta, Sand` | доп. связи; `design_label` из списка, код — нормализация имени |

После появления колонок §5.2 — `AvailableColorsExpander` переходит на тройное сопоставление.

## 7. Расширение схемы БД (миграция)

### `catalog_fabric_collections`

```sql
material_kind            VARCHAR(32) NOT NULL DEFAULT 'Ткань'
texture                  VARCHAR(64) NULL
price_category_line1_id  INT NULL FK catalog_price_categories
care_instructions        TEXT NULL          -- поле «Уход», вручную
available_colors_note    TEXT NULL          -- сырой текст кол. R (если не разворачиваем)
import_source            VARCHAR(64) NULL
import_row_hash          VARCHAR(64) NULL
```

### `catalog_fabric_collection_colors`

```sql
design_code              VARCHAR(64) NOT NULL DEFAULT ''
design_label             VARCHAR(255) NULL   -- отображаемое название цветодизайна
composition              TEXT NULL
martindale               INT NULL
properties               TEXT NULL
roll_width_cm            SMALLINT NULL
density_gsm              SMALLINT NULL
import_comment           TEXT NULL
swatch_media_id          INT NULL FK media_files   -- фото на связи, не на catalog_colors
pbr_media_id             INT NULL FK media_files
cert_media_id            INT NULL FK media_files
source_photo_url         VARCHAR(512) NULL
```

Уникальный индекс: `(fabric_collection_id, design_code)` где `design_code != ''`.

### `catalog_price_categories` (расширение)

```sql
price_min                INT NULL
price_max                INT NULL
-- label остаётся полной подписью для отображения
```

### `catalog_colors`

Без новых полей для импорта. Справочник «Цвет (группа)» — только `label` / `slug`.

### Служебные таблицы импорта

`catalog_import_runs`, `catalog_import_media_queue` — без изменений (см. предыдущую версия плана).

## 8. UI в админке

### `/admin/fabric-collection/index`

1. **Таблица ценовых категорий ткани** — номер, название, диапазон (редактирование inline). Источник при первом импорте — лист «Справочники».
2. Карточка **«Импорт из реестра»** (upload, dry-run, update, media).
3. Список коллекций (как сейчас).

### `/admin/fabric-collection/form` (редактирование коллекции)

Поля коллекции: категория ткани, название, фактура, уход, категория А+, категория Линия 1, доступные цвета (текст/список).

Блок цветов: **модальное окно** «Добавить цвет» (цвет + код + фото), таблица связей.

### Импорт: пауза при конфликте

После предпросмотра или в процессе импорта, если найден дубликат **коллекция + код**:

- Экран / модалка: описание конфликта (строка Excel, существующая запись, отличия).
- Кнопки: **«Пропустить эту строку и продолжить»**, **«Обновить существующую»** (если включено обновление), **«Отменить импорт»**.
- Выбор запоминается для оставшихся аналогичных конфликтов в сессии (опционально: «применить ко всем»).

### `/admin/fabric-collection/import-report/{id}`

Отчёт: строка | коллекция | код | цвет (группа) | действие | фото | сертификат | примечание.

```
  FabricRegistryRowDto.php

  MediaImportService.php
  FabricMediaNaming.php
  … resolvers для URL
```

### Алгоритм импорта одной строки (обновлённый)

```
1. Пропуск: пустые C/D, строка-пример (шаблон disk...)
2. Проверка дубликата (коллекция + design_code) → конфликт → пауза (§2.4, §8)
3. Upsert CatalogFabricCollection (C, B, H, F, G, R-текст)
4. CatalogColor по «Цвет» (если не пусто и валидно), иначе color_id = NULL
5. Upsert CatalogFabricColor: design_code/label = D, тех. поля E, J–M, S
6. Разворот палитры §5.2 / §5.3 — доп. связи
7. Медиа §5.1: прямая ссылка → swatch; иначе skip; Q → cert
8. import_run stats
```

## 10. Медиа (именование файлов)

**Папка:** `fabrics` (`MediaFolder::SLUG_FABRICS`).

| Тип | Шаблон | Привязка |
|-----|--------|----------|
| Swatch | `{collection_slug}-{design_code}-swatch.{ext}` | `catalog_fabric_collection_colors.swatch_media_id` |
| PBR | `{collection_slug}-{design_code}-pbr.zip` | `pbr_media_id` |
| Сертификат | `{collection_slug}-{design_code}-cert.pdf` | `cert_media_id` |

Обработка прямых ссылок (Яндекс, Mail.ru файл) — в фазе 1. Папки и неоднозначные URL — пропуск фото (§5.1), без блокировки импорта.

## 14. Критерии готовности MVP

1. Поля §2 отображаются и редактируются в админке (коллекция + модалка цвета).
2. Импорт файла Анны v2 создаёт коллекции и связи без дублей по `(коллекция, design_code)`.
3. Цвета в справочнике — простые названия; пустой «Цвет» допустим на связи.
4. Дубликат коллекция+код → пауза с выбором продолжить/отменить.
5. Фото: прямая ссылка загружается; папка/пусто — связь без фото, не ошибка.
6. Ценовые категории из «Справочников», редактирование в «Тканях».
7. Dry-run — отчёт без записи в БД.
