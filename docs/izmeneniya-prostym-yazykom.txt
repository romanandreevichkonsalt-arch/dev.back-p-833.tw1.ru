Значительные изменения проекта — простым языком
back-dev (API и админка «Фабрика»), август 2025 — сентябрь 2026

Ниже — не полный changelog, а сгруппированная картина: сколько раз меняли «правила игры» в ключевых местах.


────────────────────────────────────────
Каталог: как показываем товары в списке
────────────────────────────────────────

Логику выдачи и сортировки в каталоге пересматривали примерно 7 раз (каждый раз менялось поведение API для фронта):

1. Старый формат — простой список через устаревшие URL (/menu/products и т.п.).

2. Каталог v3 — один большой API (/catalog/menu, /catalog/products): фильтры, сортировки, фасеты; старые адреса оставили как алиасы.

3. «Круговая» выдача (round-robin) — товары идут по очереди из разных моделей, а не подряд все варианты одной модели.

4. Та же «круговая» схема распространили на все режимы сортировки (цена, новинки, популярное) и добавили правила, чтобы не слипались одинаковые коллекции ткани; сдвиг цветов при листании страниц.

5. Режим collection=true — ответ API другой формы: не плоский список, а блоки по линейкам (Артемида, Адриано…), своя пагинация.

6. «Приоритетные» SKU — часть товаров принудительно показывается выше остальных (и в каталоге, и в поиске).

7. Отдельный режим sort=alphabet — унификация алфавитной сортировки.

Дополнительно (не сортировка, но меняли контракт листинга): swatches/цвета в карточке списка; dual price для дилера; фильтры color/texture — исправили приём нескольких значений из URL.


────────────────────────────────────────
Импорт прайса / Excel моделей
────────────────────────────────────────

Шаблон и правила импорта моделей менялись крупными шагами 4 раза, плюс несколько точечных дополнений:

1. Первый импорт из прайса Excel — коллекции, модели, матрица цен по категориям ткани (1–25), sync SKU по тканям.

2. Прайс v2 — новые колонки (габариты в мм, материалы, механизм и т.д.), другой клиентский шаблон.

3. Прайс v3 — снова сдвиг колонок (функция «спальное место», размеры спального места, логика диван/кресло).

4. Дополнение: колонки 3D (полигоны, ссылка на файл) и отдельный API загрузки 3D-файла для модели.

Отдельно: импорт перевели в фоновый режим (очередь + прогресс в админке), добавили полный purge каталога с затронутыми заказами при «жёстком» reimport.

Правила названия и slug SKU менялись отдельно от Excel — см. блок ниже (это 3–4 пересчёта всех товаров в БД).


────────────────────────────────────────
Импорт тканей (реестр Excel)
────────────────────────────────────────

2 крупные версии формата:

1. Старый реестр тканей (v1) — выведен из использования.

2. Реестр v2 — одна строка = один цвет коллекции, другие колонки (состав, martindale, фото, ценовые категории и т.д.); позже — async-импорт и клиентский шаблон «Коллекции + Цвета».

Сертификаты из импорта убрали; загрузка картинок с внешних URL (Drive, Яндекс и др.) — отдельная логика медиатеки.


────────────────────────────────────────
Как называются товары (title / slug SKU)
────────────────────────────────────────

Формулу автогенерации названия меняли 4 раза (каждый раз — миграция/backfill существующих SKU):

1. Базовая схема: тип + коллекция + цвет.

2. Добавили коллекцию ткани и design_code в название и slug.

3. Вместо общего «Диван» — label подкатегории (Прямой диван и т.д.).

4. Отдельный slug для кастом-SKU; кастом скрыт из витрины и поиска, но открывается по прямой ссылке.

Плюс: на каждую модель создаётся default SKU «… кастом» без ткани.


────────────────────────────────────────
Структура каталога в базе (не Excel)
────────────────────────────────────────

1 большая перестройка (catalog v3c): направления, категории, отказ от старых «типов»; коллекции привязаны к направлению. После этого API navigation/menu строится по новому дереву; были слияния дубликатов категорий (sofa→divan и т.п.).


────────────────────────────────────────
Поиск
────────────────────────────────────────

1 крупная смена алгоритма: вместо простого ранжирования — цепочка «исправление опечатки → точное совпадение → усечение запроса → похожие строки».

Отдельно: блок «рекомендуемые товары» в админке → отдельная выдача в bootstrap API; лимиты и round-robin в /search/products как в каталоге.


────────────────────────────────────────
Цены и скидки (дилер, корзина, заказ)
────────────────────────────────────────

Крупных смен логики расчёта — около 5:

1. Одна цена → две (розница + дилерская с персональным процентом) во всём API.

2. Промокоды и кэшбек в корзине: промокод только с выдачи дилеру; кэшбек нельзя вместе с промокодом.

3. Промокод с привязкой к модели — скидка только по строкам этой модели.

4. Кэшбек: ограничение суммы списания (баланс, subtotal, позже — не больше половины subtotal после дилерской скидки); отмена заказа откатывает начисление.

5. Акции каталога (2026-09): на одной позиции либо акция, либо промокод; акция считается от дилерской строки; в API ЛКД — баннеры, один попап, список акций.


────────────────────────────────────────
Раздел «Промо и акции» в админке
────────────────────────────────────────

Сначала сделали «как в первом ТЗ», затем 6 раз меняли задумку:

1. Попап был у каждого баннера → один общий попап на весь сайт.

2. Убрали «активен» — только даты показа.

3. Убрали служебное имя и порядок баннеров.

4. Убрали «не показывать сегодня» у попапа и приоритет акций.

5. Промокод с баннера/попапа — с большой формы на модалку «привязать промокод».

6. Новый промокод — с отдельной страницы на модальное окно на общем index.


────────────────────────────────────────
Корзина и заказы
────────────────────────────────────────

Около 4 смен контракта и поведения:

1. Гостевая корзина и заказы по X-Session-ID; слияние с аккаунтом при входе.

2. Файлы и комментарии только на позиции (не на весь заказ); оформление с multipart и itemAttachments[productId].

3. Можно создать заказ сразу с items[] без корзины (atomic create).

4. Гость: оплата ЮKassa, статус pending_payment, корзина не чистится до оплаты; чеки 54-ФЗ; webhook и проверка статуса.

Дилер: заказ как заявка менеджеру (без онлайн-оплаты).

Ответ API заказов меняли: статусы для UI, превью в списке (images + extraCount вместо старых previewImages), скачивание вложений и документов.


────────────────────────────────────────
Личный кабинет дилера
────────────────────────────────────────

1. Вместо SMS — вход по email/паролю; отдельные эндпоинты /dealer/*.

2. Профиль, бонусы, менеджер, прайс-листы — расширение API.

3. Незаполненный профиль блокирует корзину и заказы (403).


────────────────────────────────────────
Избранное
────────────────────────────────────────

1 ввод: гостевое избранное по X-Session-ID и перенос при авторизации (как у корзины).


────────────────────────────────────────
Страницы сайта (CMS → API)
────────────────────────────────────────

Несколько раз меняли, что именно уходит на фронт:

• Hero-блоки: добавили нормальные поля title/subtitle (раньше фронт путал с другими ключами).

• Главная «Коллекции»: в API id слайда = направление каталога, не старая привязка к collection.

• Новые страницы API: О нас, Вакансии (+ заявка lead type=vacancy).

• Картинки в контенте: в API отдаём крупный вариант (large), в каталоге по-прежнему medium.

• После сохранения в админке — принудительный сброс кэша API (раньше фронт видел старые данные до 15 минут).


────────────────────────────────────────
Медиа и картинки товаров
────────────────────────────────────────

• В API у картинки появились srcSet (mini/medium/large/original).

• Fallback, если у SKU нет фото — подставляем из медиатеки, чтобы листинг не был пустым.
